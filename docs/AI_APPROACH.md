# AI Approach

## Pipeline

```
Essay text
  |
  1. Preprocess (core/preprocess.py)
  |    normalize quotes/dashes/whitespace -> split paragraphs + sentences
  |    -> surface stats: word/sentence counts, avg sentence length, long sentences,
  |       lexical diversity, Flesch reading ease, Flesch-Kincaid grade
  |
  2. Analyze (core/prompts.py + core/llm.py)
  |    one LLM call (Gemini Flash; Groq gpt-oss-120b as automatic backup) with: teacher persona + feedback principles, the rubric,
  |    student level, essay type, assignment prompt, measured stats, the essay
  |    -> structured output enforced by a JSON schema (core/schema.py), including an
  |       argument-structure checklist (7 PERSUADE elements: present/absent + quote)
  |
  3. Verify (core/verify.py)
  |    every quoted excerpt is located in the essay (case/whitespace tolerant,
  |    supports "..." elisions); items whose quotes are not found are removed
  |
  4. Report (core/report.py + frontend/)
       scores, strengths, priorities, practice exercise, annotated essay with
       highlights, per-criterion detail, corrections table, Markdown export
```

## Design decisions

| Decision | Why |
|---|---|
| **Argument checklist using PERSUADE's element definitions** | Gives students a concrete map of what their argument has and lacks, and lets us measure it directly against expert annotations. |
| **Rubric-anchored scoring** with written level descriptors | Makes scores consistent and explainable, and lets us compare them with human rubric scores (ELLIPSE). |
| **Structured outputs (JSON schema)** | The UI and evaluation never have to parse free text, and every response has the same shape. |
| **Quote-grounded feedback** | Each comment points to the student's own words. That makes it specific (a stated goal of the problem) and checkable. |
| **Verification step** | LLMs can misquote. We check every quote against the essay and drop anything we can't find, then report a *grounding rate* for each essay. |
| **Pedagogical prompt** (why + next step + rewrite, prioritized, level-adjusted) | Goes beyond "surface-level grammar corrections" toward the teaching insights the problem asks for. |
| **Measured stats passed to the model** | Gives the model hard numbers (sentence length, readability) to base its comments on, so it doesn't have to guess them. |
| **Result caching** | The same essay and options always return the same report. This makes demos instant and evaluation runs repeatable. |
| **Server-side refusal fallback** | If the model's safety classifier declines an essay (for example, one about a sensitive topic), the API retries on a fallback model instead of failing. |

## Model

Free-tier models only:
- **Google Gemini Flash** (`gemini-flash-latest`) is the primary. It's the strongest free option for nuanced writing feedback and supports strict JSON-schema output.
- **Groq** (`openai/gpt-oss-120b`) is the automatic backup when Gemini is rate-limited or unavailable. It has a separate free quota and is very fast.

Both are called through their OpenAI-compatible APIs (`core/llm.py`). The client retries on rate limits and switches to plain JSON mode if a model rejects strict schemas. The pipeline then fills any fields a model leaves out, so the UI never breaks. `LLM_REASONING_EFFORT=low` keeps answers fast and within free-tier token limits. The report records which model produced it.

## Evaluation: how we measure "80%+ accuracy and relevance"

Datasets, licenses and citations: [`data/DATASETS.md`](../data/DATASETS.md). Download with `python data/download_datasets.py`.

| Metric | How | Command |
|---|---|---|
| **Error-detection recall** | 10 synthetic essays with known planted grammar errors (2 hand-written, 8 generated by the LLM). % of planted errors the system flags. | `python -m eval.generate_synthetic` (once), then `python -m eval.run_eval synthetic` |
| **Structural-flaw recall** | The same synthetic essays have planted structural flaws (missing counterargument, no conclusion, weak thesis, off-topic paragraph, clichés...). % of flaws the feedback points out, with a false-alarm rate on essays without each flaw. | same as above |
| **Analytic score agreement** | Our grammar, coherence and overall scores vs. human scores on a random sample of **ELLIPSE**. Reports % within 1 point, exact agreement, MAE, QWK and Spearman. | `python -m eval.run_eval ellipse --n 30` |
| **Argument-structure accuracy** | Our checklist (lead, position, claim, counterclaim, rebuttal, evidence, conclusion) vs. **PERSUADE 2.0 expert annotations**, on a sample that is half essays with a counterclaim and half without. Also reports how often feedback tells students to address the other side when experts found no counterclaim. | `python -m eval.run_eval argument --n 30` |
| **Holistic score agreement** | Our overall and argument scores vs. the human holistic score (1–6), spread evenly across score levels. Main benchmark: **PERSUADE 2.0** independent essays (no source article). Secondary: **ASAP 2.0** (all source-based, judged without the article). | `python -m eval.run_eval holistic --dataset persuade --n 30` |
| **Feedback relevance** | Team members rate each feedback item as relevant and accurate (1) or not (0). Reports the % rated relevant. | `python -m eval.run_eval relevance-export`, then `relevance-score` |
| **Grounding rate** | % of quoted items found verbatim in the essay. Shown in the UI for every report. | automatic |

Results are written to `eval/results/*.md`. Paste the tables below before submission.

| Dataset | Role | License |
|---|---|---|
| **ELLIPSE**, ~6,500 English-learner essays, grades 8–12, human analytic scores (cohesion, grammar, ...). [Kaggle](https://www.kaggle.com/datasets/mpware/ellipse-corpus) | Accuracy of grammar and coherence scores | CC BY-NC-SA 4.0 |
| **PERSUADE 2.0**, 25,000+ argumentative essays, grades 6–12, discourse-element labels + holistic scores. [Kaggle](https://www.kaggle.com/datasets/nbroad/persaude-corpus-2) | Argument feedback and holistic agreement | CC BY-NC-SA 4.0 |

| **Synthetic essays**, 10 essays with planted errors and structural flaws | Error and flaw detection | Project-authored |
| **Demo essays**, 4 essays written for this project (strong, English-learner, generic, narrative) | Demo video and UI samples | Project-authored |

- Public datasets are used **only for evaluation**: nothing is trained on them, and none of their text is committed to the repo or shipped in the app.
- **No student personal data.** The corpora are anonymized by their publishers, and we don't use their demographic columns.

## Limitations

- Originality is judged as freshness of ideas and expression. The system does not check for plagiarism.
- Scores are calibrated to the rubric, not to any specific school's grading. Teachers should treat them as guidance.
- One model call per essay keeps latency and cost low. A per-criterion multi-call design could go deeper on long essays.
