## 1. The problem (TCS Technology Day, "Education: Automated Essay Feedback Generator")

Teachers spend a lot of time giving detailed feedback on essays (grammar, coherence, argument strength, originality). That limits how often students get feedback, and existing tools mostly fix surface-level grammar without teaching anything.

**We must build:** an AI agent that accepts essay text and produces a **detailed, constructive feedback report** highlighting **strengths and areas for improvement**.

### What the judges will look for (from the problem statement)

| # | Deliverable | Where it lives in our repo |
|---|---|---|
| 1 | AI agent: essay in, feedback report out | `core/` + `app.py` |
| 2 | **80%+ feedback accuracy and relevance** (success metric) | `eval/run_eval.py` → `eval/results/` → table in `docs/AI_APPROACH.md`; datasets in `data/DATASETS.md` |
| 3 | Simple UI for essay submission and feedback viewing | `frontend/` |
| 4 | Documentation on feedback criteria and AI approach | `docs/FEEDBACK_CRITERIA.md`, `docs/AI_APPROACH.md` |
| 5 | Demo video showing feedback on **diverse** essays | recorded at the end (see `buildplan.md`) |
| - | GenAI capabilities: text analysis, error detection, natural language generation | all three are shown in the report |
| - | Data: public or synthetic essays, text normalization + segmentation, no personal data | `data/DATASETS.md`, `core/preprocess.py` |

### Datasets (full details: `data/DATASETS.md`)

| Dataset | Use it for | Get it |
|---|---|---|
| **ELLIPSE** ([Kaggle](https://www.kaggle.com/datasets/mpware/ellipse-corpus)), from "Feedback Prize – English Language Learning": English-learner essays with human scores for cohesion, syntax, vocabulary, phraseology, grammar, conventions | **Accuracy evaluation** of our grammar and coherence scores | `python data/download_datasets.py ellipse` (no login) |
| **PERSUADE 2.0** ([Kaggle](https://www.kaggle.com/datasets/nbroad/persaude-corpus-2)), from "Feedback Prize – Evaluating Student Writing": argumentative essays labeled with Claim, Evidence, Counterclaim, Rebuttal... + holistic scores | **Argument feedback** and holistic agreement | Kaggle login, see DATASETS.md |
| **ASAP 2.0** ([Kaggle](https://www.kaggle.com/datasets/lburleigh/asap-2-0)), successor to the Hewlett ASAP: essays with holistic scores 1–6 | **Holistic score agreement** | Kaggle login, see DATASETS.md |
| **Synthetic essays**: 2 hand-written + 8 generated by the LLM, with planted grammar errors and structural flaws (e.g. missing counterargument) | **Checking that we catch known flaws** | `python -m eval.generate_synthetic` |

### How we stand out
1. **Pedagogical, not just corrective.** Every comment quotes the student's own words, explains *why*, and gives a concrete next step plus a model rewrite.
2. **Grounded.** A verification step checks that every quote actually appears in the essay and drops anything made up. The UI shows a "grounding rate" for each report.
3. **Measured.** The report shows real, measured numbers (planted-error detection, argument structure vs. PERSUADE experts, score agreement with ELLIPSE raters, quote grounding). Nothing is estimated.
4. **Built around the brief.** The flow is Landing → Submission → Analysis → Feedback report, with the four required criteria up front. The report doubles as an educator-ready artifact (print / copy / download).

## 3. How it works

```
Browser (frontend/)                         Server (app.py -> core/)
-------------------                         -------------------------
paste essay + pick level/type
        |  POST /api/feedback
        v
                                     1. preprocess.py   clean text, split paragraphs/sentences,
                                                        compute stats (words, sentence length,
                                                        readability grade, lexical diversity)
                                     2. prompts.py      build prompt: teacher persona + rubric +
                                                        student level + stats + essay
                                     3. llm.py          ONE model call (Groq; Gemini models if Groq is
                                                        busy); output forced to match schema.py
                                     4. verify.py       find every quote in the essay; drop the
                                                        ones that aren't there
                                     5. pipeline.py     tidy scores (clamp 1-5), cache result
                                     6. report.py       build Markdown export
        <-------------------- JSON result ----------
render scores, cards, highlighted essay,
criterion tabs, corrections table, download
```

### Rubric (source of truth: `core/rubric.py`)
Four criteria, each scored **1–5**, plus an overall score:

| Key | Label | Core question |
|---|---|---|
| `grammar` | Grammar & Mechanics | Is it correct and readable at the sentence level? |
| `coherence` | Coherence & Organization | Does it flow logically? |
| `argument` | Argument Strength | Does it make and support a convincing point? |
| `originality` | Originality & Voice | Fresh ideas and voice? (Not a plagiarism check.) |

If you change the rubric, update `docs/FEEDBACK_CRITERIA.md` as well.

## 5. API contract

### `POST /api/feedback`

Request:
```json
{
  "essay": "full essay text (50-3000 words)",
  "grade_level": "High school (Grades 9-12)",
  "essay_type": "Argumentative",
  "assignment_prompt": "optional",
  "use_cache": true
}
```
Header `X-Access-Code: <code>` is required only if `APP_ACCESS_CODE` is set.

Response (abridged):
```json
{
  "essay": "normalized essay text (quotes are located in THIS text)",
  "stats": { "words": 241, "sentences": 19, "paragraphs": 6, "avg_sentence_length": 12.7,
             "long_sentences": 0, "lexical_diversity": 0.55, "flesch_reading_ease": 58.8, "grade_level": 8.2 },
  "options": { "grade_level": "...", "essay_type": "...", "assignment_prompt": "" },
  "feedback": {
    "overall_score": 3,
    "overall_summary": "...",
    "top_strengths": ["..."],
    "top_priorities": ["..."],
    "next_step_exercise": "...",
    "criteria": [
      { "criterion": "grammar", "score": 2, "summary": "...",
        "strengths":    [{ "quote": "...", "comment": "...", "verified": true }],
        "improvements": [{ "quote": "...", "issue": "...", "suggestion": "...", "example_rewrite": "...", "verified": true }] }
    ],
    "grammar_errors": [{ "quote": "it have", "correction": "it has", "error_type": "grammar", "explanation": "...", "verified": true }],
    "argument_structure": [
      { "element": "position", "present": true, "quote": "...", "verified": true },
      { "element": "counterclaim", "present": false, "quote": "", "verified": true }
    ]
  },
  "verification": { "items_checked": 24, "items_unverified": 0, "grounding_rate": 1.0, "dropped": true },
  "model": "gemini:gemini-flash-latest",   // whichever provider actually answered
  "generated_at": "2026-10-08T07:13:33+00:00",
  "from_cache": false,
  "markdown": "# Essay Feedback Report ..."
}
```
- `quote: ""` means a whole-essay or "something is missing" point (it isn't highlighted).
- `error_type` is one of: `spelling, grammar, punctuation, capitalization, word_choice, sentence_structure`.
- `argument_structure` always has 7 entries in this order: `lead, position, claim, counterclaim, rebuttal, evidence, concluding_statement` (PERSUADE 2.0 definitions, in `core/rubric.py` `ARGUMENT_ELEMENTS`). The UI shows it as a checklist in the Argument tab, hidden for narrative and descriptive essays.
- `GET /api/rubric` also returns `argument_elements` (label + definition for each).
- Errors: `422` = essay too short or too long, `401` = wrong access code, `502` = model/API failure (the message is safe to show to users).

### Other routes
- `GET /api/health` returns `{ ok, mock, model, access_code_required }`
- `GET /api/rubric` returns `{ min, max, criteria, argument_elements }`
- `GET /api/evaluation` returns `{ generated_at, metrics: [{ id, label, value (0-1), detail, n, model, run_at }] }` from `data/evaluation_summary.json`. Empty list if nothing has been measured; never estimated.
- `POST /api/practice` takes `{ task, original, attempt, grade_level }` and returns `{ verdict: improved|getting_there|not_yet, feedback, next_tip, model }`. Short feedback on one practice rewrite; not cached. Uses `PRACTICE_SCHEMA` (`core/schema.py`) and `check_practice()` (`core/pipeline.py`).
- `GET /api/samples` returns `[{ id, title, text }]`

**If you change the response shape**, update `core/schema.py`, `core/report.py`, `frontend/app.js` and `data/mock_feedback.json` together, and bump `PIPELINE_VERSION` in `core/pipeline.py` so old cached results are ignored.

## 9. Conventions and gotchas

- **File encoding:** On Windows, always pass `encoding="utf-8"` to `read_text`, `write_text` and `open`. The default codepage breaks on curly quotes.
- **Quotes must be verbatim.** The prompt and schema demand it, and `verify.py` enforces it. If many items get dropped, fix the prompt; don't loosen the verifier.
- **Vercel's file system is read-only** except `/tmp`. New cache files go to `/tmp/essay-cache` on Vercel. Committed files in `data/cache/` are read-only there but are still used.
- **Static mount comes last** in `app.py`. Any new `/api/...` route must be declared above it.
- **Keep `requirements.txt` minimal.** Everything in it is bundled into the Vercel function.
- **Don't commit** `.env`, `data/raw/` or `.venv/` (already in `.gitignore`).
- **Ownership:** each file area has one owner (see `buildplan.md`), which avoids merge conflicts. Ask before editing someone else's area.

## 10. Glossary

- **Grounding rate:** % of quoted feedback items actually found in the essay.
- **Planted-error recall:** % of deliberately inserted errors that the system flags.
- **Within-1 agreement:** % of essays where our score is within 1 point of the human score.
- **QWK:** quadratic weighted kappa, the standard agreement metric for essay scoring (1.0 = perfect agreement).
- **ELLIPSE:** public dataset of English-learner essays (grades 8–12) with human scores for cohesion, grammar and more.
- **PERSUADE 2.0:** public dataset of argumentative essays (grades 6–12) with labeled argument parts and holistic scores.
- **ASAP 2.0:** public dataset of argumentative essays with holistic scores 1–6.
- **Structural flaw:** a problem bigger than one sentence: missing counterargument, no conclusion, weak thesis, off-topic paragraph, clichés.
- **False-alarm rate:** how often the eval says a flaw was caught in an essay that doesn't have it.
- **Mock mode:** the app returns canned feedback without calling the AI, for UI work with no key.
